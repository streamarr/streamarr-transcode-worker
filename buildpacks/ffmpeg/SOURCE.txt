Corresponding Source
====================
Streamarr builds these binaries from its fork of the pinned FFmpeg build and
distributes them. The source code for FFmpeg, Streamarr's patches, the bundled
libraries, and the scripts controlling compilation is available without charge at
the repositories and exact revisions listed below. Obtain FFmpeg, its patch series
in debian/patches (Streamarr's patches are the files whose names start with
streamarr-) and the build recipes at:
https://github.com/streamarr/streamarr-ffmpeg/tree/8a984ad1cba1968dc8f1ad3e2e200041dc6bcf7a
Source archive:
https://codeload.github.com/streamarr/streamarr-ffmpeg/tar.gz/8a984ad1cba1968dc8f1ad3e2e200041dc6bcf7a

The fork's release workflow, .github/workflows/streamarr-portable.yaml, builds each
archive with ./build-linux-amd64 or ./build-linux-arm64, which run
builder/makeimage.sh and builder/build.sh for linux64 or linuxarm64 and gpl and
apply the patch series with quilt. The builder/scripts.d recipes select library
revisions, build options, generated code, and any changes in builder/patches.
These changes are part of the Corresponding Source; an unpatched library release
alone is not the complete source for a patched component. Streamarr's packaging
scripts are in buildpacks/ffmpeg in:
https://github.com/streamarr/streamarr-transcode-worker

For a Git source entry below, clone its repository and check out the listed
revision (git checkout --detach REVISION); initialize submodules when the pinned
recipe requires them. For LAME, use svn checkout -r 6531 with the listed URL.
The source entries also identify relevant generated-loader and build-support
inputs; not all such entries are standalone libraries linked into the binary.
The index also lists components that only the fork's macOS arm64 archive
contains (macarm64); this image does not include that archive.

Build-source records
====================
Some recipes clone a source without a revision, and builder/scripts.d/25-fftw3f.sh
names a revision that it does not check out. Each build records the repository
and revision that every clone resolved to, and each archive carries that record as
BUILD-SOURCES.txt. The records of the archives this image pins follow. Where a
record names another revision than the index below, the record names the source
of the binary.

License and inventory information
=================================
LICENSE.txt contains GPLv3. THIRD-PARTY-NOTICES.txt reproduces the inventoried
licenses and attribution verbatim, including FFmpeg's license overview, GPL/LGPL
texts and per-file copyright information from the locked fork revision. Identical
texts are reproduced once and referenced by SHA-256 from each component's entry.
These components retain their own copyright notices and license terms. The FDK
notice and modification notice are also retained at the paths given above.

notices/manifest binds this inventory to the source revision and both archive
checksums. notices/sources.json records component roles, architecture scope,
source revisions, build recipes, notice origins and notice SHA-256 checksums.
The file paths and checksums there identify vendored inputs in Streamarr's source
repository, not binary archives. Those texts appear by SHA-256 in the installed
THIRD-PARTY-NOTICES.txt; the individual input files are not all installed.
Header-license excerpts are marked; text may have a normalized final newline.
The two buildconf files record the binaries' configure flags used as the starting
point for the inventory; transitive static code and generated loaders were then
traced through the locked recipes and submodule/dependency pins.

System glibc shared libraries and optional GPU driver implementations are not in
the portable tarballs. Their notices belong to the image/base-system packages that
provide them. glibc startup/nonshared support is inventoried separately. GCC runtime
code is linked statically and its Runtime Library Exception is
included here. The upstream builder does not pin Implib.so: its inventory revision
identifies the notice source, and the build-source records above name the revision
that each pinned archive's build cloned.
